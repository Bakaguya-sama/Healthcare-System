# RF-2A — Service responsibility and dependency map

Ngày audit: **2026-09-16**. Phạm vi: toàn bộ **32** file `*.service.ts` trong backend. Chín service phối hợp nhiều capability được map đến từng method; 23 service còn lại được kiểm kê theo nhóm method và disposition.

> RF-10B update (2026-09-20): đây là decomposition baseline lịch sử. Runtime hiện chỉ có `modules/consultations`, `ConsultationsService` và canonical Consultation routes; toàn bộ Session facade/method/route được liệt kê bên dưới đã bị xóa. Xem contract hiện hành ở `apps/api/openapi/openapi.json`.

Tài liệu này là decomposition plan của `BE-RF-005`, không phải thiết kế feature mới và không cho phép di chuyển source hàng loạt. Public HTTP/Socket contract hiện tại phải được giữ bởi compatibility facade cho đến task cutover tương ứng.

## 1. Quy ước

| Ký hiệu | Loại trách nhiệm | Ý nghĩa                                              |
| ------- | ---------------- | ---------------------------------------------------- |
| `C`     | Command          | Thay đổi business state/persistence                  |
| `Q`     | Query            | Đọc, lọc, thống kê hoặc tạo read model               |
| `P`     | Domain policy    | Validation/rule/state transition thuần nghiệp vụ     |
| `A`     | Provider adapter | Bao Cloudinary, email, LLM, embedding hoặc transport |
| `O`     | Orchestration    | Phối hợp nhiều model/service/side effect             |

`Tx: none` nghĩa là source không dùng Mongo session/transaction. Đây là mô tả hiện trạng, không phải quyết định rằng transaction không cần thiết.

## 2. Kết luận kiến trúc

### 2.1 Hotspots và vi phạm ownership

| Service/controller     | Dependency hiện tại                                                  | Vấn đề boundary                                                                               | Owner/port đích                                                                                       |
| ---------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `AuthService`          | User, Doctor, Admin, JWT, bcrypt, mail, Cloudinary                   | Identity vừa ghi practitioner, upload tài liệu, OTP và profile assembly                       | Identity facade; Practitioner application port; `TokenPort`, `OtpPort`, `MailPort`, `FileStoragePort` |
| `AdminService`         | User, Doctor, Session, Admin, mail, notification gateway             | Admin trực tiếp sở hữu model của ba domain và gọi transport                                   | Practitioner verification, Account moderation, Admin reporting; delivery qua event/outbox             |
| `UsersService`         | User, Doctor, Patient, Admin, Review, Violation, Cloudinary          | Cross-model god query; User module làm practitioner, patient, review và moderation read model | User/Practitioner/Patient ports; profile assembler chỉ phối hợp query ports                           |
| `SessionsService`      | Session, UsersService, NotificationsService                          | Persistence và notification orchestration trộn nhau                                           | Consultation command/query facade; user summary port; notification intent port                        |
| `SessionsController`   | SessionsService + SessionsGateway                                    | Controller tự dựng và emit domain/realtime event                                              | Command use case trả outcome; event publisher phát sau commit                                         |
| `ChatService`          | Message, Session, Cloudinary                                         | Message owner đọc Session trực tiếp và quản lý upload lifecycle                               | Consultation access policy port; Message command/query; Attachment port                               |
| `ChatController`       | ChatService + ChatGateway                                            | Controller phát `new_message`; Socket path phát qua gateway riêng                             | Một `MessagePublished` application event/port dùng chung HTTP và Socket                               |
| `ReviewsService`       | Review, Doctor, Session                                              | Review tự kiểm tra Consultation và ghi rating projection bằng rollback thủ công               | Consultation eligibility port; Review command/query; RatingProjectionService trong transaction        |
| `HealthMetricsService` | HealthMetric, UsersService, AiAssistantService, NotificationsService | CRUD, rule, daily aggregation, BMI, AI và notification cùng class                             | Health command/query, rule evaluator, statistics, BMI projection, alert coordinator qua ports         |
| `AiAssistantService`   | AiConversation, legacy Message, RAG, prompt, LLM, Cloudinary         | Conversation CRUD/query, media, RAG và LLM orchestration cùng facade; đọc Message domain khác | AI command/query facade; response orchestrator; media port; canonical AI persistence                  |
| `NotificationsService` | Notification + NotificationsGateway                                  | DB write/read đồng thời emit Socket; read `findOne` có side effect mark-read                  | Notification command/query; delivery event/outbox adapter                                             |

Không service nào trong chín hotspot mở Mongo transaction. Các chuỗi `write -> email/socket/upload/AI` có thể để lại trạng thái dở dang; các chuỗi nhiều write của Auth, Review, Chat và HealthMetric đặc biệt cần transaction hoặc compensation được thiết kế rõ ở task domain sau.

### 2.2 Controller/gateway audit

- Auth, Users, Reviews, HealthMetrics và Admin controller chủ yếu parse/delegate/map response; tiếp tục giữ mỏng.
- `SessionsController.create/confirm/reject/complete/cancel` dựng payload và emit Socket. Di chuyển orchestration này vào application event publisher ở `BE-RF-040/043`.
- `ChatController.sendMessage` trực tiếp emit `new_message`, trong khi `ChatGateway.send_message` có flow riêng. Hợp nhất ở `BE-RF-041/043` để tránh hai event contract.
- `AiAssistantController.searchConversations/getConversation` tự dựng query primitive từ raw query; chuẩn hóa DTO ở `BE-RF-006`. Interceptor đọc `process.env` trực tiếp được xử lý ở `BE-RF-012`.
- `NotificationsController` có các biến `result` rồi trả nguyên trạng, có thể rút gọn khi đổi facade; không ưu tiên trước ownership fix.

Thứ tự bắt buộc trong mỗi slice:

1. Bổ sung characterization test cho method đang chuyển nếu coverage hiện tại chưa đủ.
2. Định nghĩa application port/repository contract nhỏ theo capability; không tạo generic `BaseRepository`.
3. Extract policy/mapper thuần trước, sau đó query hoặc command độc lập.
4. Giữ facade cũ delegate sang implementation mới; controller/gateway chưa đổi contract.
5. Chuyển cross-module model injection thành owner port/facade.
6. Đưa email/socket/upload/LLM thành intent/port; outbox chỉ được nối khi foundation sẵn sàng.
7. Chạy unit/characterization/integration; chỉ xóa nhánh legacy sau cutover evidence.
